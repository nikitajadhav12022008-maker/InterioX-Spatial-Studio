## What the app does
- **4 building types**: House, Office, Clinic/OPD, Café & Restaurant — each
  with its own rooms, catalog, and AI-generated layouts.
- **2D planner** with real collision detection (rotated-rectangle math, not
  just bounding boxes), a **3D viewport**, and a **first-person walkthrough**
  — each of those for a single room *or* the whole building at once (toggle
  in the toolbar), with a "🚶 Walk the Building" shortcut from the overview.
- **Realistic 3D furniture**: every catalog item is built from several
  primitive shapes (seat + backrest + legs, counter + ledge + kickboard, bed
  + frame + pillow, etc.) rather than a single colored box — see "About the
  3D models" below for what this can and can't do here.
- **Two sign-in methods**: mobile number + OTP (two-step verification), or
  email + password — both with distinct sign-up/log-in entries.
- **Ergonomic audit** (pathway clearance, screen viewing distance, window
  access, lighting) for one room or the whole building.
- **"Raise it with a designer"**: a directory of nearby designers, a request
  form with **photo upload**, tracked per designer.
- **Star ratings** for the app itself, with a running average.
- **AR / VR**: best-effort WebXR, a "open in new tab" link, and a QR code —
  see the AR/VR section below for why this is the realistic ceiling here and
  how to get the full experience.

## About the 3D models — what "realistic" means here
This app can't load external 3D model files: the sandboxed environment I
built it in only allows loading *scripts* from a short list of CDNs, not
images, textures, or `.glb`/`.gltf` model files from anywhere. So there is no
path in this project to real photographic furniture models — that would need
a licensed asset library and a normal (non-sandboxed) hosting setup.

What I did instead: every item is generated in code from multiple shapes
(boxes, cylinders, cones) proportioned to look like the real object — a sofa
has a seat, backrest, arms and legs; a hospital counter has a raised ledge
and kickboard; a bed has a frame, mattress and pillows. It's stylized
low-poly, not photorealistic, but it's a real improvement over flat colored
boxes and stays fast in the browser. If you need true photorealism for the
submission, the clean next step is to swap `buildItemMesh()` in `app.js` to
load `.glb` files from a real asset library (e.g. Sketchfab CC0 models,
Poly Pizza, or a paid pack) via `THREE.GLTFLoader` — that only works once
the site is hosted normally (see "Hosting" below), not inside this preview.

## AR / VR — why it doesn't work in the chat preview, and how to make it work
**Short version:** the code is correct WebXR; the *embedded preview inside
this chat* blocks camera and headset access, so `navigator.xr` is often
unavailable there no matter what the page does. That's a browser permissions
policy on the embedding iframe, not a bug you can fix from inside the page.

**What actually gets you real AR/VR — pick one:**
1. **Open the link in its own browser tab** (not embedded) — tap "Open in a
   new tab" in the app's AR/VR dialog, or just visit the artifact URL
   directly in Chrome/Safari. Once it's a normal top-level tab, the browser
   can prompt for camera/headset permission like any other site.
2. **Scan the QR code** shown in the same dialog with your phone — this opens
   the same link as a normal mobile page, outside any iframe.
3. **Host it yourself** (see below) and open *that* URL. This is the most
   reliable path for a submission/demo, since you control the environment.

**Requirements once it's not embedded:**
- **AR**: Android phone, Chrome (ARCore-capable device), HTTPS. iOS Safari
  doesn't support WebXR AR as of this writing — iOS AR needs Apple's own
  Quick Look/AR Quick Look pipeline instead, which is a separate integration.
- **VR**: a WebXR-capable headset browser — Meta Quest's built-in browser is
  the easiest to test with; open the URL there directly.
- **HTTPS is mandatory** — WebXR refuses to run on plain HTTP (localhost is
  exempted for local dev).

**If you want a guaranteed-working demo for your submission**, the walkthrough
mode (WASD + drag-to-look, no headset needed) works everywhere right now,
embedded or not — lean on that for the live demo, and mention AR/VR as
"implemented via WebXR, testable once hosted" in your writeup.

## Making it public / accessible to everyone
This chat's link (`https://claude.ai/artifact/...`) is private to your
account until you turn on sharing for it — that's a toggle in the artifact's
own share menu in the Claude UI, not something achievable from inside the
page. For a submission that needs a public URL you don't have to manage
sharing settings for, host the standalone file yourself instead:

1. **GitHub Pages** (free): create a repo, drop `standalone-single-file.html`
   in as `index.html`, enable Pages in repo Settings → Pages. You get a
   public `https://yourname.github.io/repo/` URL.
2. **Netlify / Vercel** (free): drag-and-drop the `frontend` folder onto
   Netlify's dashboard, or `vercel deploy` — both give an instant public URL,
   and both are plain static hosts so `index.html` + `styles.css` + `app.js`
   work as-is.
3. Any static host works, since there's no server-side code in the frontend.

For the backend, `docker compose up` + `uvicorn` (see `backend/README.md`)
runs it locally; for a public backend URL, deploy it to Render, Railway, or
a small VM and update the frontend's `fetch()` base URL to point at it
(the current frontend stores everything in the browser and doesn't call the
backend yet — see the next section).

## Connecting frontend to backend (next step, not done automatically)
Right now the two are independent: the frontend works standalone with
browser storage, and the backend is a separate, runnable API. To wire them
together: replace the `localStorage`-based functions in `app.js`
(`getUsers`, `getProjects`, `getReviewRequests`, `getRatings`, and the OTP
generation in `sendOtp`) with `fetch()` calls to the matching backend
endpoints listed in `backend/README.md`. That's a mechanical swap since the
data shapes already match what the backend expects.
